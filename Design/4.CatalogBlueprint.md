## job.yaml
- run it as a kubernetes job, usign K8sJobber package wich takes a job.yaml definition and overrides the name and injects a label
- let user set all env-vars of job in a user-defined job-env-secret.yaml (secret)
  - job.yaml should `container.envFrom.secretRef` from job-env-secret.yaml
    https://kubernetes.io/docs/reference/kubernetes-api/workload-resources/pod-v1/#Container
- follow recomendations of K8sJobber package:
  - one-shot-jobs:  "backoffLimit: 0" + "restartPolicy: Never"   

```yaml
apiVersion: batch/v1
kind: Job
metadata:
		name: mycatalog-1-0-0-zzz                    # a) auto-overridden with unique <prefix + timestamp> (ex: data-processor-1739062631)
	  labels:
	    k8sjobber-id: mycatalog-1-0-0-zzz     # b) auto-added to job and pod
spec:
		backoffLimit: 0               # c) mandatory so it behaves as a one-shot job
		template:
	    metadata:
	      labels:
	        k8sjobber-id: my-catalog-1-0-0-zzz     # b) auto-added to job and pod
	    spec:
		    restartPolicy: Never      # c)
		    containers:
		    - name: main
		      image: mycatalog-1-0-0
          envFrom:
            - secretRef:
                name: mycatalog-env

```



## job-env-secret.yaml
Example: 
- like this but using a secret instead of configmap
- https://kubernetes.io/docs/tasks/configure-pod-container/configure-pod-configmap/#configure-all-key-value-pairs-in-a-configmap-as-container-environment-variables
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: mycatalog-env
type: Opaque
data:
  PASS: WTRueXM3ZjEx
  USER: cHJvZHVzZXI=

```
